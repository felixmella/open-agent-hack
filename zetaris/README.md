# Zetaris setup

Lightning SQL that registers FactSync Chile's sources in Zetaris and builds the views the agents read. Run each file as an admin user, one statement per request, with `scripts/zetaris_sql.py` (it uses `ZETARIS_ADMIN_API_KEY`). Dry-run first:

```powershell
.venv\Scripts\python scripts\zetaris_sql.py zetaris\01_sources_create.sql --dry-run
.venv\Scripts\python scripts\zetaris_sql.py zetaris\01_sources_create.sql
```

Add `--skip-exists` when re-running a file whose tables already exist; the `CREATE OR REPLACE` views are simply replaced.

| Order | File | What it creates |
|---|---|---|
| 1 | `01_sources_create.sql` | REST database `FACTSYNC_REST`, container `factsync`; INE Census 2024 by comuna (ArcGIS) and Wikidata population statements (SPARQL), with their views |
| 2 | `scripts/prepare_ine_projections.py`, `scripts/prepare_ine_census2002.py`, then `scripts/upload_filestore.py` | the two INE files in `data/official/`, copied into the Zetaris file store |
| 3 | `02_official_create.sql` | INE Census 2017 by comuna and its urban/rural split (ArcGIS), INE projections 2002–2035 and Census 2002 (file store), with their views |
| 4 | `03_wikipedia_create.sql` (generated by `scripts/build_wikipedia_sql.py`) | each comuna's Spanish and English Wikipedia article (MediaWiki API, 50 titles per request) |
| 5 | `04_unified_create.sql` | `official_population` (every official figure, by series), the infobox views, `population_picture` (every claim, keyed by CUT), and `source_catalog` (what the agents can read and what each source covers) |
| 6 | `05_readonly_grants.sql` | SELECT on the `factsync` views for the app's read-only user; check it with `scripts/verify_readonly.py` |

The app reads only the `factsync` views, with a General-role user that holds SELECT on them and nothing else.

Every new object was checked by comparing its rows with the source it reads (the CSV in `data/official/`, or a direct call to the public API).
